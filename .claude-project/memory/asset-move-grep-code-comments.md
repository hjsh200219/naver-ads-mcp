2026-08-13 `docs/references/` 정리 중, 자산 파일 참조가 **두 종류**로 갈린다는 것을 확인했다:

| 유형                | 실례                                                                                           | 이동 시 증상                      | 그린 빌드가 잡는가 |
| ------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------- | ------------------ |
| 테스트 하드 의존    | `tests/e2e-reference-parity.test.ts:135` ← xlsx 파일명 하드코딩                                | 테스트 즉시 실패                  | ✅ 잡는다          |
| 코드 주석 경로 참조 | `src/excel/styles.ts:2`, `src/dashboard/artifact-html.ts:2`, `src/analyzer/weekly-prompt.ts:8` | 아무 일도 안 일어남 — 경로만 썩음 | ❌ 못 잡는다       |

**Why:** 주석 안의 경로는 tsc·vitest가 읽지 않는다. 그래서 자산을 옮긴 뒤에도 lint/typecheck/test가 전부 통과하며 "문제 없음"이라는 잘못된 신호를 준다. 반대로 테스트 하드 의존은 즉시 터지므로, 두 유형이 섞여 있으면 "테스트 통과 = 안전"이라는 추론이 절반만 맞는다. grep이 두 유형을 동시에 잡는 유일한 수단이다.

**How to apply:**

- 문서·자산 파일 이동·삭제·개명 **전에** `grep -rn "<파일명>" src/ tests/ docs/ --include="*.ts" --include="*.md" --include="*.json"` 실행. 파일명 전체와 디렉터리명 양쪽으로 각각 검색.
- 참조가 있으면 이동을 포기하거나, 코드·테스트·주석까지 같은 커밋에서 함께 갱신한다.
- 이동 후 `npm test` 통과는 **필요 조건일 뿐 충분 조건이 아니다.** grep 결과가 0건이어야 안전.
